# F-001: `.ods` Seçiminden DXF Tablo Bloğu Üretimi

**Status:** `REVIEW` — kod ve otomatik testler tamam; AutoCAD'de manuel doğrulama bekliyor
**Priority:** `P0 — Critical`
**Assigned Agent:** Claude Code (2026-08-13)
**Requested By:** Kadir Akar
**Target Date:** no deadline

---

## Goal

Kullanıcı, LibreOffice Calc'ta biçimlendirdiği bir tablo alanını (ör. `Mahal!B3:C500`) seçip tek
bir komutla, sayfada gördüğüne benzeyen, kendi kendine yeten bir AutoCAD blok tanımına
dönüştürebilsin. Tablo çizime blok olarak girer; kaynak veri değiştiğinde aynı komut yeniden
çalıştırılır ve blok yeniden tanımlandığında çizimdeki tüm örnekler güncellenir. Çizim hiçbir
harici dosyaya bağımlı kalmaz.

Stil, kullanıcının zaten bildiği araçta — Calc'ta — düzenlenir; öğrenilecek yeni bir biçim dosyası
yoktur (ADR-002).

- [x] **AC-4:** Seçim içindeki gizli satır ve sütunlar çıktıda yer almaz; kalan satır/sütunlar

- [x] **AC-12:** Aynı girdi ile iki kez çalıştırıldığında üretilen tablo geometrisi aynıdır

## Technical Design

### Bağımlılıklar

| Paket | Amaç |
|---|---|
| `odfpy` | `.ods` okuma — biçim bilgisiyle birlikte (`pandas` stil bilgisini düşürdüğü için yeterli değil) |
| `ezdxf` | DXF yazma |
| `fontTools` | Metin genişliği ölçümü (sığdı/sığmadı kararı için) |
| `tomllib` | Config okuma (Python 3.11+ stdlib) |

Paketleme: PyInstaller tek dosya `.exe`. Ofis PC'lerinde Python kurulu değil ve kullanıcı IT
sorumlusu değil.

### Katmanlı Yapı

```
cli.py          → argüman ayrıştırma, config birleştirme, çıkış kodu
ods_reader.py   → .ods → SheetModel   (tek yer: odfpy burada kalır)
model.py        → SheetModel ve yardımcı tipler
metrics.py      → TTF ile metin genişliği ölçümü, sığdı/sığmadı
geometry.py     → SheetModel → çizilecek varlıkların listesi
dxf_writer.py   → varlıklar → ezdxf blok tanımı → dosya
report.py       → [TBL …] satırları, konsol + .report.txt
```

`geometry.py` `odfpy`'yi görmez, `ods_reader.py` `ezdxf`'i görmez. Bugün tek okuyucu var; bu bir
yalıtım dikişi, spekülatif bir eklenti mimarisi değil.

> **Şablondan sapma:** Bu repodaki `CLAUDE.md` ve `Architectural_Mandates.md`, şablondan gelen
> TypeScript/command-pattern varsayılanlarını taşıyor (`IUndoableCommand`, `CommandManager`,
> repository soyutlaması). Bu proje Python ve tek yönlü bir dönüştürücü — mutasyon yok, undo yok,
> DB yok. O mandate'ler burada uygulanmaz; şablon metinleri henüz projeye göre yeniden yazılmadı.

### Data Model

```python
Rgb = tuple[int, int, int]

@dataclass(frozen=True)
class Border:
    width_mm: float          # 0.0 = kenarlık yok
    color: Rgb

@dataclass(frozen=True)
class Borders:
    left: Border
    right: Border
    top: Border
    bottom: Border

@dataclass(frozen=True)
class FontSpec:
    size_pt: float
    bold: bool
    italic: bool
    color: Rgb

@dataclass(frozen=True)
class Cell:
    row: int                 # SheetModel içinde 0-tabanlı
    col: int
    text: str                # .ods'teki GÖRÜNEN metin (biçimlenmiş)
    h_align: Literal["left", "center", "right"]
    v_align: Literal["top", "middle", "bottom"]
    font: FontSpec
    borders: Borders
    fill: Rgb | None
    padding_mm: float
    col_span: int            # 1 = birleştirme yok
    row_span: int
    covered: bool            # başka bir hücrenin birleştirmesi tarafından kapsanıyor

@dataclass
class SheetModel:
    source_ref: str                  # "Mahal!B3:C500" — hata mesajlarında kullanılır
    col_widths_mm: list[float]       # gizli sütunlar çıkarılmış hâliyle
    row_heights_mm: list[float]      # gizli satırlar çıkarılmış hâliyle
    cells: dict[tuple[int, int], Cell]
```

`.ods` uzunlukları cm/inç/pt karışık gelebilir; okuyucu hepsini **mm**'ye normalize eder. cm → çizim
birimi çevrimi yalnızca `geometry.py`'de, tek bir çarpanla yapılır.

### CLI

```
tabletodxf <kaynak.ods> --sheet <ad> --range <A1:B2> --out <dosya.dxf> --block <BLOK_ADI>
```

| Bayrak | Varsayılan | Açıklama |
|---|---|---|
| `--sheet` | — | zorunlu; sayfa adı |
| `--range` | — | zorunlu; `B3:C500` biçiminde |
| `--out` | — | zorunlu; çıktı DXF yolu |
| `--block` | — | zorunlu; blok adı (önek dahil) |
| `--config` | `./tabletodxf.toml` varsa | config dosyası yolu |
| `--scale` | `10.0` | 1 cm kaç çizim birimi |
| `--frame` | `0.35` | dış sınırdaki çerçeve kalınlığı, mm (`0` = kapalı) |
| `--overflow` | `condense` | `condense` (yatay sıkıştır) \| `mtext` (düzenlenebilir kutu) \| `marker` (`###`) \| `full` (taşmasına izin ver) |
| `--text-style` | `ONCU_TBL_TEXT` | DXF metin stili adı |
| `--font` | `NotoSans-Regular.ttf` | stile bağlanacak TTF |
| `--layer-prefix` | `ONCU_TBL` | katman ad alanı |
| `--dxf-version` | `R2013` | R2013 ve üstü |
| `--report` | `<out>.report.txt` | rapor dosyası yolu |
| `--verbose` | kapalı | `[TBL DEBUG]` satırlarını da bas |

Öncelik: CLI bayrağı > config dosyası > yerleşik varsayılan.

Çıkış kodları: `0` başarılı (uyarılar olabilir), `1` doğrulama/veri hatası, `2` kullanım hatası.

### Config (TOML)

> **Güncel değil.** Ayar yüzeyi F-002 ile tipli ve bölümlenmiş bir katmana taşındı; yukarıdaki
> CLI tablosu da yalnızca sık kullanılan bayrakları gösterir (her ayara `--set` ile erişilir).
> Tam ve güncel liste: `DOCS/Features/F-002.md` ve `tabletodxf.example.toml`.

```toml
[layout]
scale_cm_to_units = 10.0
frame_mm          = 0.35

[overflow]
mode = "condense"

[text]
style_name = "ONCU_TBL_TEXT"
font_file  = "NotoSans-Regular.ttf"

[layers]
prefix = "ONCU_TBL"
```

Config yüzeyi kasıtlı olarak küçüktür. Görünümle ilgili her şey `.ods`'ten gelir (ADR-002); buraya
yalnızca formatın taşıyamadığı şeyler girer.

### Katman Şeması

| Katman | İçerik |
|---|---|
| `<prefix>_GRID` | Tüm kenarlık çizgileri. Kalınlık **polyline global width'i** ile taşınır — sayfadan geldiği ve kenar başına değiştiği için BYLAYER olamaz |
| `<prefix>_TEXT` | Hücre metinleri |
| `<prefix>_FILL` | Opak beyaz zemin + arka plan dolguları (düz desenli `HATCH`) |
| `<prefix>_OVERFLOW` | Yalnızca `###` işaretleri. Boş katman = çizimde hiç taşma yok |

Katmanlar işlev taşır, stil değil. `_OVERFLOW`'un ayrı olması, alıcının tek katmanı dondurarak temiz
bir pafta almasını sağlar; ve "bu çizimde taşan hücre var mı?" sorusu tek bakışta cevaplanır.

### Geometri Üretim Sırası

1. `.ods` oku → `SheetModel` (gizli satır/sütunlar bu aşamada düşürülür)
2. Doğrula — seçimi kesen birleştirme, önbelleksiz formül. Hata varsa **hiçbir dosya yazmadan** dur
3. Izgara koordinatlarını hesapla: kümülatif genişlik/yükseklik × ölçek. Origin = seçimin sol üst
   köşesi, `(0, 0)`. Y ekseni aşağı doğru negatif
4. Seçimin tamamını kaplayan opak beyaz zemin, ardından hücre dolguları (düz desenli `HATCH`) —
   önce, arkada kalsınlar diye
5. Kenarlıklar — aşağıdaki birleştirme ve çakışma kurallarıyla
6. Metinler — sığdırma kontrolü sonrası tam metin, `MTEXT` kutusu ya da `###`
7. Hepsini `BlockTableRecord` içine sar
8. `$INSUNITS = 0` yaz, DXF sürümünü ayarla
9. DXF ve `.report.txt` dosyalarını yaz

### Kenarlık Kuralları

- **Paylaşılan kenar tekilleştirmesi.** A hücresinin sağ kenarı ile B hücresinin sol kenarı aynı
  çizgidir; `.ods` ikisini de saklar. İkisi tanımlıysa ve farklıysa **kalın olan kazanır**; eşitse
  biri çizilir. Aynı çizgi asla iki kez çizilmez.
- **Eş doğrultulu birleştirme.** Kalınlığı ve rengi aynı olan, ardışık ve eş doğrultulu kenar
  parçaları tek bir `LWPOLYLINE`'a birleştirilir. Hücre başına ayrı `LINE` üretmek varlık sayısını
  patlatır.
- **Birleştirilmiş hücreler.** Birleşik alanın içinde kalan ızgara parçaları çizilmez; yalnızca dış
  sınırı çizilir. `covered` hücreler hiçbir şey üretmez.
- `width_mm == 0.0` olan kenar çizilmez.
- **Dış çerçeve.** Tablonun dış sınırındaki parçalar tek tip bir kalınlığa yükseltilir:
  `max(--frame, sınırdaki en kalın mevcut kenarlık)`. Ayrı bir dikdörtgen **eklenmez** — eklenseydi
  hücrelerin kendi dış kenarlıklarıyla birebir aynı yere düşüp çakışık çift çizgi üretirdi. Çerçeve
  bu yüzden zemin `HATCH`'inin sınırıyla birebir çakışır. Tek tip olması, eş doğrultulu
  birleştirmenin çerçeveyi dört çizgiye indirmesini sağlar.

### Metin Kuralları

- Yerleşim, hücre kutusu eksi `padding_mm` içinde `h_align` / `v_align` çiftine göre yapılır.
  Birleştirilmiş hücrede kutu, birleşik alanın tamamıdır.
- Metin yüksekliği `font.size_pt` → mm → çizim birimi olarak çevrilir.
- **Sığdırma kontrolü:** ölçülen metin genişliği, kullanılabilir genişlikten (hücre − padding)
  büyükse hücre taşmıştır.
- Taşma davranışı `--overflow` ile belirlenir:
  - `mtext`: metin, tanımlı genişliği **hücrenin metin alanına eşit** bir `MTEXT`
    olarak çizilir; satır bölmeyi AutoCAD yapar ve alıcı genişlik tutamağıyla düzeltebilir
  - `condense` (varsayılan): metin hücreye sığacak şekilde **yatay sıkıştırılır** (DXF genişlik çarpanı).
    Çarpan en geniş satırdan türetilir, hücredeki tüm satırlara aynısı uygulanır; okunabilirlik
    tabanı `MIN_WIDTH_FACTOR = 0.25`, tabana dayanınca rapora `clamped=yes` düşer
  - `marker`: kullanılabilir genişliği dolduracak sayıda `#` çizilir,
    `<prefix>_OVERFLOW` katmanına; `[TBL WARN] … reason="text overflow"` raporlanır
  - `full`: metnin tamamı yazılır, hücre sınırını taşmasına izin verilir
- **Hiçbir modda kırpma yok.** Kırpma veriyi sessizce gizler; `###` gizlendiğini söyler, `full`
  hiç gizlemez. Metin kısaltma/elips mantığı bilinçli olarak yoktur.
- Sığdırma kontrolü metin ve sayı ayrımı yapmaz.

### Error Cases

Mesaj biçimi:

```
[TBL ERROR] op=<işlem> cell=<Sayfa!Ref> reason="<kısa neden>" <ek alanlar>
```

Değerler tırnak içinde — boşluk içeren metinler alan ayrıştırmasını bozmasın diye. `grep '\[TBL WARN\]'`,
`grep 'op=render_cell'`, `grep 'cell=Mahal!'` ile filtrelenebilir.

| Kod | Tetikleyici | Seviye | Davranış |
|---|---|---|---|
| `SRC_FORMAT` | Girdi uzantısı `.ods` değil | ERROR | Durur. Mesaj, Calc'ta ODF olarak kaydetmeyi söyler |
| `SRC_NOT_FOUND` | Dosya yok / okunamıyor | ERROR | Durur |
| `SRC_SHEET_NOT_FOUND` | `--sheet` adı dosyada yok | ERROR | Durur; mevcut sayfa adlarını listeler |
| `SRC_RANGE_INVALID` | Aralık ayrıştırılamıyor ya da sayfa sınırları dışında | ERROR | Durur |
| `SRC_STALE` | Okunan `x.ods`'in yanında daha yeni `mtime`'a sahip `x.xlsx`/`x.xls` var | WARN | Devam eder. ADR-001'in ürettiği tek yeni hata modu |
| `MERGE_CROSSES_SELECTION` | Bir birleştirme seçim sınırını kesiyor | ERROR | Durur; birleştirme aralığını yazar. Sessiz kırpma yok |
| `FORMULA_NO_CACHE` | Formül hücresinde önbellek değeri yok | ERROR | Durur |
| `CELL_OVERFLOW` | Metin hücreye sığmıyor | WARN | Devam eder; `###` + `_OVERFLOW` katmanı |
| `FONT_NOT_FOUND` | TTF dosyası bulunamıyor | ERROR | Durur. Ölçüm yapılamadan çıktı üretmek anlamsız |
| `SELECTION_EMPTY` | Gizli satır/sütunlar düşünce geriye hiç satır ya da sütun kalmıyor | ERROR | Durur |

Örnekler:

```
[TBL ERROR] op=read_selection cell=Mahal!C12 reason="merge crosses selection edge" merge="C12:D14"
[TBL ERROR] op=read_cell cell=Mahal!F8 reason="formula has no cached value"
[TBL WARN]  op=render_cell cell=Mahal!C17 reason="text overflow" avail_mm=21.0 text_mm=48.6 text="Zemin kat koridoru"
[TBL WARN]  op=check_source reason="newer sibling workbook found" ods="mahal.ods" sibling="mahal.xlsx"
```

Kısmi çıktı üretilmez: ERROR seviyesindeki her durum, hiçbir dosya yazılmadan önce yakalanır.

## Agent Notes

### Open Questions

- [X] **Blok yeniden tanımlamanın DXF tarafındaki sözdizimi.** `-INSERT blokadı=dosya.dwg` deyimi
      DWG için bilinen bir yöntem; `.dxf` yolunun kabul edilip edilmediği sürüme göre değişebilir.
      Kabul edilmiyorsa iki yedek var: (a) çıktıyı DWG'ye çevirmek, (b) DXF'in yanına adımları
      yapan bir `.scr` dosyası da üretmek. **Hâlâ açık — AutoCAD'de denenmeli.**
      Yüksek engel değil, ama akış buna bağlı.
      *Uygulamanın bu soruya katkısı:* çıktı hem blok tanımını **hem de** origin'de tek bir
      `INSERT`'ünü içeriyor. Böylece `-INSERT` yolu tutmazsa bile dosya doğrudan açılıp tablo
      panoya alınabiliyor; ve DESIGNCENTER / "blok ekle" akışları da çalışıyor.
- [x] **`ezdxf`'in metin ölçüm yardımcıları.** ~~`ezdxf` font ölçümü için bir sarmalayıcı sunuyor
      olabilir.~~ **Karara bağlandı (`ezdxf` 1.4.4): `fontTools` doğrudan kullanılıyor.**
      `ezdxf.fonts` çözümü *isimle* yapıyor ve sistem font önbelleğine bakıyor; burada kullanıcı
      `--font` ile açık bir **dosya yolu** veriyor ve ölçümün paketlenmiş `.exe` içinde de birebir
      aynı çıkması gerekiyor (AC-12). Bkz. `metrics.py` modül başlığı.
- [x] **`.ods` hücre dolgusu (`fo:padding`) her zaman mevcut mu?** **Hayır.** Stil zincirinde hiç
      `fo:padding*` bulunmayan hücreler var. Varsayılan `0.97 mm` alındı — LibreOffice'in `Default`
      hücre stiline yazdığı `0.097cm` ile aynı (`ods_reader.DEFAULT_PADDING_MM`). Kenar başına
      dolgu verilmişse en büyüğü kullanılıyor; `Cell` tek bir `padding_mm` taşıyor.

### Uygulama Sırasında Alınan Kararlar

Şartnamenin sessiz kaldığı ya da kendi içinde çeliştiği yerler. Hepsi koda yorum olarak da işlendi.

| Karar | Gerekçe |
|---|---|
| **Hata durumunda rapor dosyası da yazılmaz** | AC-11 "her çalıştırma rapor yazar" diyor, Test Planı "hata sonrası rapor yolu boş" diyor. İkincisi seçildi: yarım bir `.report.txt` bir sonraki çalıştırmada başarılı sanılabilir. Hata satırı `stderr`'e basılır. |
| **Çıktıya blok tanımının yanına bir `INSERT` de konur** | Tanımı olup örneği olmayan DXF boş açılır; görsel doğrulama (manuel adım) imkânsızlaşırdı. AC-1 tek blok tanımı istiyor, ihlal yok. |
| **Dış çerçeve: dışarı ofsetli, tek kapalı polyline** | Kullanıcı tercihi (2026-08-13), iki adımda oluştu. Önce sınır parçalarının kalınlığı yükseltiliyordu; kalınlık `lineweight` iken bu doğruydu, çünkü lineweight'in geometrik kalınlığı yok. Global width'e geçince **eksen çizgisinin nerede durduğu önem kazandı**: AutoCAD genişliği eksenden iki yana açıyor, yani eksen tam sınırda olsaydı bandın yarısı tablonun içine düşüp ilk hücrelerin kenarlığını ve metnini örterdi. Çözüm: sınır parçaları **silinir**, yerine ekseni sınırdan `width/2` kadar **dışarı** kaydırılmış tek **kapalı** polyline konur. Böylece bandın **iç kenarı** tam tablo sınırına (zemin `HATCH`'inin sınırına) oturur, çerçeve içeri yemez, dışarı büyür. Kapalı olması köşelerin gönyeli birleşmesini sağlar — dört ayrı çizgide köşelerde çentik kalıyordu. Kalınlık yine `max(--frame, sınırdaki en kalın mevcut kenarlık)`. |
| **`condense` modu: taşan metni hücreye yatay sıkıştırarak sığdır** | Kullanıcı bildirimi (2026-08-13), gerçek çizimde görüldü. `MTEXT` kutu genişliğini ayarlamak yetmiyor: **AutoCAD otomatik heceleme yapmıyor**, dolayısıyla boşluksuz uzun bir metin kutu ne kadar dar olursa olsun bölünecek yer bulamayıp taşmaya devam ediyor. `condense`, DXF genişlik çarpanını (`TEXT.width`, yatay ölçek) `kullanılabilir genişlik / ölçülen genişlik` olarak ayarlıyor; yükseklik değişmiyor. Çarpan en geniş satırdan türetilip hücredeki tüm satırlara uygulanıyor — satır başına çarpan harf genişliklerini satırdan satıra zıplatırdı. Okunabilirlik tabanı `0.25`; altına inmek gerekiyorsa çarpan tabanda tutuluyor ve rapora `clamped=yes` düşüyor, çünkü okunamayan bir tablo üretmektense taşmayı bildirmek doğru. |
| **Taşan hücre `###` olmaktan çıktı; `MTEXT` modu eklendi** | Kullanıcı tercihi (2026-08-13). `###` verinin gizlendiğini söylüyordu ama çizim üzerinde yapılabilecek hiçbir şey bırakmıyordu. `MTEXT` metni gizlemiyor, satır bölmeyi AutoCAD yapıyor, ve alıcı genişlik tutamağıyla düzeltebiliyor. Tanımlı genişlik = hücre genişliği − iki yandan dolgu. Kutular `_OVERFLOW` katmanında kaldığı için "boş katman = taşma yok" tanısı korunuyor. Kısa süre sonra varsayılanlık `condense`'e geçti (aşağıdaki satır); `mtext` bölünebilir metinlerde hâlâ daha okunaklı. |
| **Varsayılan taşma modu `condense`** | Kullanıcı tercihi (2026-08-13), `mtext` gerçek çizimde denendikten sonra. Kutu genişliğini ayarlamak yetmedi: AutoCAD heceleme yapmadığı için boşluksuz uzun metin her genişlikte taşmaya devam etti. `condense` elle müdahale gerektirmiyor — tablo doğrudan basıma hazır çıkıyor — o yüzden varsayılan o oldu. `mtext` bayrakla duruyor. |
| **`MTEXT` içeriği kaçırılır (`\`, `{`, `}`, satır sonu)** | `MTEXT` biçimlendirmeyi metnin içinde taşır; kaçırılmazsa `{` içeren bir hücre çizimde metnin bir kısmını yutar. Satır sonu `\P`'ye çevrilir ve bu dönüşüm en sonda yapılır, yoksa kendi eklediği ters bölü yeniden kaçırılır. |
| **Kenarlık kalınlığı `lineweight` ile değil, polyline global width'i ile taşınır** | Kullanıcı tercihi (2026-08-13), gerçek çizimde görüldükten sonra. `lineweight` bir **görüntüleme/çizdirme** niteliğidir: `LWDISPLAY` kapalıysa ekranda hiç görünmez, baskıda CTB/STB kalem tablosu onu ezebilir — yani sayfadaki kalınlık hiyerarşisi alıcının ayarlarına bağlı kalıyordu. Global width gerçek geometridir; her zoom'da görünür, her kalem tablosunda aynı basar. `lineweight` artık **hiç yazılmıyor** (BYLAYER'da kalıyor) ki hangisinin geçerli olduğu belirsiz olmasın. Kalınlık da bir uzunluk olduğu için tablonun geri kalanıyla aynı ölçek çarpanından geçer. *Kabul edilen sonuç:* sayfadaki `0.06pt` (0.021 mm) çizimde de 0.021 birimdir ve saç teli gibi görünür; kalınlaştırmak Calc'ta yapılır. |
| **Kaydırmalı hücre de `marker` alır** | Kullanıcı bildirimi (2026-08-13). Önceki hâli kaydırmalı hücreleri `###`'ten muaf tutuyordu; kaydırmanın yaygın olduğu gerçek sayfada bu, `--overflow marker`'ı `full` ile birebir aynı yapıyordu (11 taşan hücrenin 11'i de `mode=wrap` alıyordu). `overflowed` zaten **kaydırmadan sonra** hesaplanıyor — oraya düşen hücre kaydırmaya rağmen sığmıyor demektir, kullanıcı işaret istediyse işaret görmeli. Raporda `mode` artık uygulanan modu yazıyor, kaydırma ayrı bir `wrap=yes` alanı. |
| **Sığdırma kontrolü metnin kendi ekseninde yapılır** | Kullanıcı bildirimi (2026-08-13), gerçek çıktıda görüldü. Şartname sığdırmayı yalnızca genişlik üzerinden tanımlıyordu; 90° döndürülmüş bir başlıkta metnin uzadığı yön hücrenin **yüksekliğidir**. Genişliğe bakmak dar sütundaki her dikey başlığı sahte taşma yapıyor ve tüm başlık satırını `###`e çeviriyordu. Yerleşim artık `(yön, dik)` ortonormal çerçevesinde hesaplanıyor; 0°'de eski formüle birebir indirgeniyor. |
| **`fo:wrap-option="wrap"` gerçekten kaydırma yapar** | Kullanıcı bildirimi (2026-08-13). Önceki davranış — kaydırmalı hücreyi tek satır sayıp `###` basmak — Calc'ta düzgün görünen açıklama sütunlarını çizimde okunamaz hâle getiriyordu. Kaydırma açgözlü ve kelime sınırında. Kaydırmalı hücre **hiçbir zaman** `###` üretmez: kaydırma zaten sığdırma yöntemidir. Kaydırılmış blok satır yüksekliğini aşarsa `[TBL WARN] reason="wrapped text taller than cell"` basılır, metin yine de çizilir. |
| **Seçimin tamamına opak beyaz zemin serilir** | Kullanıcı tercihi (2026-08-13). Calc'ta "dolgu yok" olan hücre ekranda beyaz görünür, saydam değil — ama dolgusuz hücre için hiç varlık üretmezsek çizimde altındaki geometri görünür ve ADR-002 (sayfada ne görüyorsan çizimde o) bozulur. Hücre başına beyaz dolgu yerine **tek dörtgen**: N yerine 1 varlık, hücreler arasında dikiş yok, renkli dolgular üstüne biniyor. Kabul edilen sonuç: tablo opaktır, üzerine bindiği geometriyi örter. |
| **Arka plan dolgusu `SOLID` değil düz desenli `HATCH`** | Kullanıcı tercihi (2026-08-13). `HATCH` düzenlenebilir sınır, saydamlık ve çizim sırası taşır; AutoCAD tarafında hücre dolgusu için beklenen varlık tipi. Yan fayda: `SOLID`'in köşeleri halka değil `Z` sırasında isteme tuzağı ortadan kalkar. Hücre başına bir `HATCH` üretilir — aynı renkleri tek varlıkta toplamak dosyayı küçültürdü ama tek bir hücrenin dolgusunu seçmeyi imkânsız kılardı. |
| **Aralığın kaynakta tanımlı olmayan satır/sütunları hata değil** | AC-5 sondaki boş satırların çizilmesini istiyor, ama Calc kullanılmayan satırları dosyaya hiç yazmıyor. Katı davranmak AC-5'i tipik durumda erişilemez kılardı. Tanımsız satır/sütun Calc varsayılanıyla (`4.52mm` / `22.58mm`) doldurulur. `SRC_RANGE_INVALID` yalnızca bozuk aralık ve ODF tavanı (1048576×16384) için. |
| **Açık hizalama yoksa değer tipine göre karar verilir** | Calc sayıyı sağa, metni sola yaslar ve bunu `.ods`'e `fo:text-align` olarak **yazmaz**. Taklit edilmezse sayfada sağa yaslı görünen her sayı çizimde sola kayardı — ADR-002'nin doğrudan ihlali. |
| **DXF metin yüksekliği = büyük harf yüksekliği** | TTF tabanlı stilde DXF `height` cap height'tır, em boyu değil. `font-size`'ı doğrudan yazmak metni sistematik olarak ~%40 büyük gösterirdi. Genişlik em boyuyla, yükseklik `capHeight/upem` oranıyla çevrilir. |
| **Kenarlık kalınlığı en yakın geçerli DXF lineweight'e yuvarlanır** | DXF `lineweight` yalnızca sabit bir değer kümesini kabul eder; sayfadan gelen `0.06pt` gibi değerler o kümede yok. 0'a yuvarlanmaz — kaynakta görünür olan kenarlık çizimde de görünür kalır. |
| **Gizli satır/sütun bir birleştirmenin içinden geçerse birleştirme daralır** | AC-4 gizli olanların çıktıda yer almamasını istiyor. `C4:D4` birleşikken D gizlenirse birleşik alan tek sütuna iner. |
| **`--dxf-version` R2013 altını reddeder** | AC-9 Kiril/CJK istiyor, bu da TTF metin stili demek. Eski sürümler taşımaz; sürüm bir görünüm ayarı değil, doğruluk koşulu. |
| **Kenarlıkta `double`/`dashed` tek düz çizgiye iner** | Kenarlık DXF'te bir `LWPOLYLINE`; taşıyabildiği görsel nitelik kalınlık ve renk. |
| **Konsol kodlaması sertleştirilir (`errors="replace"`)** | Türkçe/Kiril karakter basamayan bir konsolda üretim `UnicodeEncodeError` ile yarıda kalmamalı. Rapor **dosyası** her zaman UTF-8. Kodlama zorlanmaz — cp1254 Türkçe'yi zaten doğru basar. |

### Bilinen Sınırlar (kabul edilmiş)

Ayrıntı ve gerekçe: `README.md` → "Bilinen sınırlar".

- **Kalın/italik görsel olarak ayrışmaz** — tek TTF'e bağlanıyoruz. Sayfadaki kalın başlık çizimde
  normal ağırlıkta çıkar ve ölçüm normal metriklerle yapılır. WYSIWYG'de en görünür açık bu.
  *Çözümü ucuz:* `--font-bold` eklenip stil ikiye ayrılabilir. Ayrı bir karar gerektirir.
- **Kaydırmada kelime bölünmez** — tek başına satıra sığmayan kelime kendi satırında taşar
  (`###` olmaz). Calc uzun kelimeyi ortadan bölebiliyor; bölme noktası fonta ve sürüme göre
  değiştiği için tabloda öngörülemeyen kayma yaratırdı.
- **Varsayılan font CJK içermez** — `NotoSans-Regular.ttf` Kiril içerir, CJK içermez. AC-9'un CJK
  yarısı `--font` ile uygun bir TTF verilmesini gerektirir.
